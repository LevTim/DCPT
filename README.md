Варіант 9

Об’єднати “замовлення” з довідником товарів (створити окремий DataFrame з категоріями/собівартістю), виконати merge, знайти рядки без відповідників і оцінити їхню частку.

Скрипт створює два набори даних (замовлення та довідник товарів), виконує ліве з'єднання (Left Join) , автоматично маркує походження кожного рядка, знаходить "осиротілі" транзакції та вираховує відсоток замовлень, для яких відсутня інформація у довіднику.

Навіщо це можна використовувати?

Синхронізація ІТ-систем (Data Reconciliation): Автоматична перевірка узгодженості даних між різними платформами (наприклад, вітрина інтернет-магазину та складська база 1С/ERP або CRM).

Аудит та контроль якості даних (Data Quality Assurance): Пошук "осиротілих" записів, дублікатів або помилок ручного введення (наприклад, менеджер продав новий товар, але не заніс його картку в базу).

Бізнес-аналітика (Business Intelligence): Швидка оцінка масштабу проблеми (відсоток втрат або розбіжностей), щоб зрозуміти, чи це одноразовий збій системи, чи критична системна помилка.

Логіка роботи:

Ініціалізація DataFrame-ів (імітація вивантаження даних з реальних таблиць або CSV/Excel файлів).

Виконання об'єднання таблиць (pd.merge) за спільним ключем (унікальним ідентифікатором товару product_id).

Додавання системного індикатора для маркування походження об'єднаних даних (з якої саме таблиці прийшов рядок).

Векторна фільтрація загального масиву для виокремлення виключно тих рядків, що не знайшли відповідників у довіднику.

Математичний розрахунок частки (відсотка) проблемних записів відносно загальної кількості замовлень.

Виведення структурованих результатів для подальшого аналізу.

Головні "фішки" (Особливості коду)

Left Join (Ліве з'єднання): Використання параметра how='left' гарантує збереження всіх без винятку транзакцій. База замовлень береться за жорстку основу, що унеможливлює втрату фінансових даних під час злиття, навіть якщо товар повністю відсутній у базі.

Smart Indicator (Розумний маркер indicator=True): Вбудований інструмент Pandas, який автоматично створює колонку _merge. Це позбавляє необхідності писати складні цикли та умови для перевірки збігів, дозволяючи миттєво ідентифікувати рядки системними статусами both, left_only або right_only.

Автоматичне оброблення пустот (NaN Handling): При відсутності даних з правого боку Pandas самостійно заповнює порожнечі значеннями NaN (Not a Number) і непомітно змінює тип числових колонок (з int на float), що запобігає падінню скрипта через помилки типів (TypeErrors) під час подальших обчислень.

Векторна фільтрація (Boolean Masking): Використання конструкції merged_df['_merge'] == 'left_only'  для фільтрації даних. Цей метод працює на рівні C-бібліотек під капотом Pandas, що робить його в сотні разів швидшим за звичайний перебір рядків через цикл for. Це критично важливо при роботі з базами на мільйони записів.

Метричний підхід: Скрипт не просто ізолює помилкові рядки, а одразу видає готову бізнес-метрику (відсоток відхилень від норми). Це дозволяє автоматизувати алерти (наприклад, якщо unmatched_percentage > 5%, скрипт може відправляти повідомлення в Telegram/Slack).
